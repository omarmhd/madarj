# قاعدة البيانات — التصميم والمبررات

## المبدأ الحاكم

الجداول مقسّمة إلى **عائلتين منفصلتين تماماً**:

| العائلة | الطبيعة | من يكتب فيها |
|---|---|---|
| **جداول المحتوى** | تُقرأ كثيراً، تُكتب نادراً | مستورد المحتوى فقط (`content:import`) |
| **جداول التقدّم** | تُكتب باستمرار | المستخدمون |

**لماذا الفصل مهم:** المحتوى ثابت ومشترك بين كل المستخدمين — يُخزَّن مرة واحدة ويُخزَّن مؤقتاً (cache) بلا انتهاء. التقدّم شخصي ومتغيّر. خلطهما يعني إبطال الـ cache عند كل نقرة من أي مستخدم.

## جداول المحتوى

### `weeks`
الأسابيع الأربعة والعشرون. صف واحد لكل فصل من الكتاب.

| العمود | النوع | الشرح |
|---|---|---|
| `number` | tinyint | 1–24 — المفتاح الحقيقي المستخدم في الروابط |
| `module` | tinyint | 1–4 — الوحدة |
| `title_en` / `title_ar` | string | عنوان الفصل |
| `objectives` | json | مصفوفة الأهداف: `[{ en, ar }]` |
| `pron_section` | tinyint | رقم قسم النطق داخل الفصل |
| `is_review` | boolean | أسابيع 6، 12، 18، 24 — بنيتها مختلفة |

### `days`
سبعة صفوف لكل أسبوع. **هذا الجدول هو أساس الصرامة الزمنية.**

| العمود | النوع | الشرح |
|---|---|---|
| `week_id` | FK | — |
| `number` | tinyint | 1–7 |
| `focus` | string | ملخص اليوم |
| `tasks` | json | `[{ order, label, minutes, ref }]` — المهام الخمس |

**لماذا `tasks` كـ JSON وليس جدولاً؟** لأنها تُقرأ دائماً كمجموعة كاملة، ولا يُستعلم عن مهمة منفردة أبداً. جدول منفصل يعني `join` بلا فائدة.

### `vocabulary`
مئة كلمة لكل أسبوع — 2400 صف إجمالاً.

| العمود | الشرح |
|---|---|
| `group` | التصنيف داخل الأسبوع: `family`, `numbers`… |
| `word`, `ipa`, `arabic`, `example` | المحتوى |
| `position` | الترتيب داخل المجموعة |

### `dialogues` + `dialogue_lines`
حواران لكل أسبوع. الأسطر في جدول منفصل لأن عددها متغير وقد نحتاج ترقيمها.

### `exercises`
**الجدول الأهم في طبقة المحتوى.** كل التمارين بأنواعها في جدول واحد.

| العمود | الشرح |
|---|---|
| `type` | `fill_blank` · `multiple_choice` · `true_false` · `match` · `correct_error` · `order_words` · `free_text` |
| `prompt` | نص السؤال |
| `payload` | json — يختلف حسب النوع |
| `answer` | json — الإجابة الصحيحة |
| `points` | الدرجة |

**لماذا جدول واحد لكل الأنواع؟** لأن الاستعلام دائماً *"أعطني تمارين الأسبوع الثالث"* ولا يهم النوع. الاختلاف في العرض لا في التخزين.

مثال على `payload` و `answer`:

```json
// type: fill_blank
payload: { "before": "She", "after": "(be) a teacher." }
answer:  { "accepted": ["is"] }

// type: multiple_choice
payload: { "options": ["is", "are", "am"] }
answer:  { "correct": 0 }

// type: correct_error
payload: { "sentence": "He work in a bank." }
answer:  { "accepted": ["He works in a bank."] }
```

### `minimal_pairs`
أزواج التمييز الصوتي — تغذّي لعبة الاستماع.

| العمود | الشرح |
|---|---|
| `group_label` | مثال: *short i vs long ee* |
| `ipa` | `/ɪ/ vs /iː/` |
| `word_a`, `word_b` | الكلمتان |

## جداول التقدّم

### `enrollments`
تسجيل المستخدم في الدورة. **صف واحد لكل مستخدم.**

| العمود | الشرح |
|---|---|
| `track` | `A` (ساعة) أو `B` (ساعتان) |
| `started_on` | تاريخ البدء — منه تُحسب الجدولة |
| `current_week`, `current_day` | موضعه الآن |
| `timezone` | لحساب "اليوم" بشكل صحيح |

### `day_completions`
**قلب نظام الصرامة.** صف واحد لكل يوم أنجزه المستخدم.

| العمود | الشرح |
|---|---|
| `tasks_done` | json — أي المهام الخمس أُنجزت |
| `completed_at` | لحظة اكتمال كل المهام — `null` يعني اليوم مفتوح لكن غير مكتمل |
| `minutes_spent` | من مؤقّت الواجهة |

**قيد فريد:** `(user_id, week_id, day_number)` — يستحيل تكرار اليوم.

**قاعدة القفل:** اليوم `n+1` لا يُفتح إلا إذا وُجد صف لليوم `n` بـ `completed_at` غير فارغ.

### `exercise_attempts`
كل محاولة على كل تمرين. لا نكتفي بالأخيرة — عدد المحاولات مؤشر تعليمي.

### `recordings`
**قرار معماري مهم: الملف الصوتي لا يُرفع إلى الخادم.**

| العمود | الشرح |
|---|---|
| `week_number` | — |
| `duration_seconds` | — |
| `self_score` | تقييمه الذاتي |
| `local_ref` | مفتاح الملف في `IndexedDB` عند المستخدم |

**لماذا؟** ثلاثة أسباب:
1. **التكلفة** — 24 تسجيلاً × ألف مستخدم = عشرات الجيجابايت
2. **الخصوصية** — لن نحتفظ بتسجيلات صوتية لآلاف الأشخاص
3. **لا حاجة** — قيمة التسجيل في أن يسمعه هو، لا نحن

### `week_gates`
قفل الأسابيع. الأسبوع لا يُفتح إلا بإتمام سابقه، وأسابيع المراجعة تشترط درجة.

| العمود | الشرح |
|---|---|
| `unlocked_at` | متى فُتح |
| `test_score` / `test_max` | نتيجة اختبار الأسبوع إن وُجد |
| `passed_at` | متى اجتازه |

### `streaks`
السلسلة اليومية. صف واحد لكل مستخدم — يُحدَّث لا يُضاف إليه.

### `review_cards`
التكرار المتباعد بخوارزمية **FSRS**. صف لكل مستخدم لكل كلمة.

| العمود | الشرح |
|---|---|
| `due_at` | موعد المراجعة القادمة — الفهرس الأهم في النظام |
| `stability`, `difficulty` | متغيرات FSRS |
| `state` | `new` · `learning` · `review` · `relearning` |

**الفهرس الحرج:** `(user_id, due_at)` — الاستعلام اليومي هو *"أعطني بطاقات هذا المستخدم المستحقة الآن"*.

## قرارات تصميمية تستحق التوضيح

| القرار | البديل المرفوض | السبب |
|---|---|---|
| `tasks` كـ JSON | جدول `day_tasks` | تُقرأ دائماً كمجموعة، والـ join بلا فائدة |
| كل أنواع التمارين في جدول واحد | جدول لكل نوع | الاستعلام لا يفرّق بين الأنواع |
| التسجيلات محلياً | S3 | التكلفة والخصوصية |
| `number` بجانب `id` في `weeks` | الاعتماد على `id` | الروابط `/week/3` يجب ألا تتأثر بإعادة الاستيراد |
| `enrollments` منفصل عن `users` | أعمدة في `users` | يسمح مستقبلاً بأكثر من مسار لنفس المستخدم |
